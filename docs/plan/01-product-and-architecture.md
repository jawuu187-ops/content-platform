## 1. أ. تحليل المنتج

### 1.1 تفكيك OnlyFans إلى نطاقات وظيفية

قسمتُ ما تفعله OnlyFans فعليًا (لا ما تسوّقه) إلى 12 نطاقًا. كل نطاق أصبح وحدة (module) في
المعمارية، وله معايير قبول مستقلة في خطة التنفيذ.

| # | النطاق | ما يوجد في OnlyFans | ما نبنيه | ما نضيفه للمنافسة |
|---|---|---|---|---|
| 1 | الهوية والوصول | بريد/كلمة مرور، 2FA، جلسات | Passkeys + TOTP، أجهزة موثوقة، استعادة آمنة | قفل بيومتري داخل التطبيق، تنبيه دخول جديد، إدارة جلسات لكل جهاز |
| 2 | التحقق من العمر والهوية | تحقق عمر إلزامي (UK/EU/US)، KYC للصنّاع | تكامل مع مزوّد تحقق معتمد + بوابة صلاحيات (entitlement gate) | تحقق مُقيَّد بالخصوصية (Zero-knowledge proof/over-18 token) كما تقترح EUDI |
| 3 | الكتالوج والاكتشاف | بحث، تصنيفات، اقتراحات، روابط دعوة | بحث + تصنيف + ترتيب + صفحة عامة SFW | صفحة عامة "آمنة للعمل" لكل صانع (بوابة SEO لا تحتوي عريًا) |
| 4 | المحتوى والوسائط | منشورات، صور، فيديو، رسائل مقفلة، مكتبة | نصوص/صور/فيديو، جدولة، مسودات، ألبومات، Vault | تحكم دقيق في الجمهور (tier/segment)، PPV منتهي الصلاحية، Welcome message تلقائي |

| 7 | الإكراميات | Tips على المنشور والملف | Tips + أهداف تمويل (Tip goals) | Tips مرتبطة بحدث (بث/هدف) + شكر آلي |
| 8 | الرسائل | DM، رسائل مقفلة، رسائل جماعية | DM + وسائط مقفلة + قوالب + تصنيف | صندوق "Mass DM" بشرائح، ردود سريعة، حماية من الاحتيال (كشف طلبات دفع خارج المنصة) |
| 9 | المال | أرصدة، سحب، عمولة 20% ثابتة | دفتر قيد مزدوج، عمولة متدرجة، محفظة، سحوبات | عمولة متدرجة بالحجم، تقارير مالية قابلة للتدقيق، تسوية يومية |
| 10 | الثقة والسلامة | مراجعة، بلاغات، إيقاف | تصنيف آلي + طابور بشري + استئناف + سجل تدقيق | مطابقة بصمات CSAM إلزامية، حساب سمعة الصانع، إنفاذ آلي للسياسة |
| 11 | الحماية | علامة مائية، URLs موقعة | URLs قصيرة العمر، ربط الجلسة، علامة مائية لكل مشاهد، كشف تسريب | بصمة جنائية (session token مضمّن) لتحديد مصدر التسريب |
| 12 | التشغيل والإدارة | لوحة إدارة، تقارير | لوحة إدارة معزولة، SSO + مفتاح مادي، أربعة أعين للمال | Feature flags، وضع صيانة، سجلات تدقيق موقعة بـ hash chain |

### 1.2 ما يجب إضافته لأن المنافسة ليست على عدد الميزات فقط

1. **مستويات عضوية متعددة** — OnlyFans لا يملكها فعليًا؛ هي أقوى أداة لزيادة ARPU.
2. **الدفع بلا كرت** — في أسواق MENA/أمريكا اللاتينية/آسيا تفشل الكروت؛ محفظة مُسبقة الدفع
   (شراء رصيد بالكريبتو/القسائم/التحويل المحلي) هي ما يجعل التجديد التلقائي ممكنًا.
3. **صفحة عامة SFW** — تفتح باب SEO ومشاركة الروابط على الشبكات الاجتماعية، وهو ما لا تفعله
   OnlyFans. هذا هو أيضًا جسر الحضور في متاجر التطبيقات (منتج SFW منفصل).
4. **حماية من التسريب كخدمة** — كشف تسريب + إزالة DMCA + تقرير للصانع؛ ميزة بيعية حقيقية.
5. **إدارة وكالات** — وكالات تدير عدة صنّاع؛ نموذج "مساحة عمل" متعدد الصنّاع بملكية واضحة
   وتدقيق كامل، وهو سوق كبير ومدفوع.
6. **عمولة متدرجة** بدل 20% ثابتة — ورقة تفاوض مباشرة مع كبار الصنّاع.
7. **شفافية الأرباح** — كشف حساب لكل معاملة، حالة السحب، وسجل التسوية (أكبر شكوى عند المنافسين).

### 1.3 أنواع المستخدمين والصلاحيات

| الدور | النطاق | صلاحيات أساسية | قيود إلزامية |
|---|---|---|---|

| عضو فريق الصانع | تفويض صانع | إدارة محددة (رسائل/محتوى) | لا سحب، لا تغيير أسعار، سجل تدقيق |

### 1.4 التدفقات الأساسية (7 تدفقات حرجة)

1. **تسجيل مشترك**: بريد → تحقق → تحقق عمر → تصفح → اشتراك → مشاهدة.
2. **صانع جديد**: تسجيل → تحقق بريد/هاتف → KYC + 2257 → موافقة → إنشاء صفحة → أول منشور → أول سحب.
3. **اشتراك**: اختيار المستوى → دفع (كرت/محفظة/كريبتو) → تفعيل فوري → تجديد → إلغاء → انتهاء.
4. **PPV**: منشور مقفل → معاينة → شراء → فتح → إيصال + سجل.
5. **رسالة مدفوعة**: صانع يرسل رسالة مقفلة → إشعار → فتح → شراء → وصول.
6. **سحب**: رصيد → طلب → مراجعة (أربعة أعين) → دفع عبر مزوّد → إشعار → كشف.
7. **بلاغ/مخالفة**: بلاغ → تصنيف آلي → طابور → قرار → إجراء (إزالة/إيقاف) → استئناف → سجل.

### 1.5 قرار حرج: توزيع تطبيق Android

**الحقيقة المؤكدة (مصادر في `docs/vendors/payments-and-distribution.md`):** لا يوجد تطبيق
OnlyFans في Google Play أو App Store، لأن سياسة Google Play تمنع المحتوى الجنسي، وقاعدة
Apple 1.1.4 تمنع المواد الجنسية الصريحة. النتيجة: **تطبيق المحتوى الكامل لا يمكن نشره في
المتجرين.** أي خطة تفترض غير ذلك ستنهار عند التسليم.

البدائل الثلاثة، والتوصية:

| البديل | الوصف | المزايا | العيوب |
|---|---|---|---|
| A — APK مباشر + PWA | توقيع ذاتي، تنزيل من موقعنا، تحديث داخل التطبيق | تحكم كامل، لا قيود سياسة، تحديث فوري | احتكاك تنزيل، تحذيرات "مصدر غير معروف"، فقدان ثقة المتجر |
| B — متجر بديل (Aptoide/Amazon) | نشر APK في متجر طرف ثالث | احتكاك أقل من A | قواعد متجر ثالث غير مضمونة الاستقرار |
| C — منتج SFW منفصل في Play | تطبيق "محتوى آمن" للاكتشاف + تسجيل، والمحتوى الحصري عبر الويب | حضور في المتجر، اكتساب مجاني | منتج ثانٍ (تكلفة + علامة منفصلة)، لا يرضي "تطبيق واحد كامل" |

**التوصية: A كأساس + C كمرحلة لاحقة اختيارية.** التطبيق الأصلي (Compose) يُبنى بالجودة
الكاملة ويُوزَّع APK/AAB موقّعًا من موقعنا، مع PWA كنسخة ثانية من نفس الـ API. قرار C يحتاج
موافقتك لأنه يعني علامة ثانية.

## 2. ب. التصميم المعماري

### 2.1 المخطط العام

```
   Android (Kotlin/Compose)      Web/PWA (Next.js)        Admin (React, نطاق معزول)
            |                          |                            |
            +-------- Cloudflare (WAF, bot, rate-limit, DDoS) ------+
                                       |
                        API Gateway (Go, mTLS داخلي)
                                       |
  ┌──────────────────────────────────────────────────────────────────┐
  │  Modular monolith (Go) — عملية API + عملية Workers               │
  │  identity · catalog · content · media · subscriptions · billing  │
  │  ledger · payouts · messaging · moderation · notifications ·     │
  │  analytics · admin · entitlements                                │
  └──────────────────────────────────────────────────────────────────┘
        |                    |                     |
   PostgreSQL 18+        Valkey            S3-compatible object store
   (مصدر الحقيقة)      (كاش/حدود)          (masters + renditions)
        |
   ClickHouse (تحليلات)  ·  OpenSearch (بحث)  ·  Outbox + NATS (أحداث)
        |
   مسار الوسائط: رفع resumable مباشر → فحص/تطبيع → ترميز (HLS/fMP4)
                 → تسليم موقّع قصير العمر + علامة مائية لكل مشاهد
```

### 2.2 مبادئ غير قابلة للتفاوض

1. **المال له مصدر واحد**: دفتر قيد مزدوج append-only. الأرصدة إسقاطات محسوبة، لا أعمدة قابلة للتعديل.
2. **معاملة قاعدة البيانات أولًا**: كل حدث خارجي يُكتب في جدول outbox داخل نفس المعاملة، ويُنشر بعد commit.
3. **الوسائط لا تمر عبر الـ API**: رفع مباشر للـ storage بروابط موقعة؛ التسليم من CDN برمز قصير العمر.
4. **المحتوى خاص افتراضيًا**: كل طلب وسائط يمر عبر قرار صلاحية (entitlement) مسجّل.
5. **الإدارة نطاق أمني منفصل**: نطاق مختلف، SSO + مفتاح مادي، IP allow-list، أربعة أعين للمال.
6. **كل شيء قابل للتدقيق**: سجلات منظمة، traces، metrics، وسجل تدقيق موقّع hash chain.
7. **استقلال عن المزوّد**: محوّلات (adapters) للدفع والتسليم والتحقق — لا SDK لمزوّد داخل منطق النطاق.

### 2.3 قواعد البيانات (المخططات الرئيسية)

| Schema | الجداول الأساسية | ملاحظات |
|---|---|---|
| `identity` | `users`, `credentials`, `sessions`, `devices`, `roles`, `role_grants`, `mfa_factors`, `recovery_tokens`, `login_events` | جهاز = device fingerprint + مفتاح عميل |
| `verify` | `age_checks`, `kyc_cases`, `consent_records`, `model_releases` | لا تخزّن وثيقة الهوية؛ خزّن نتيجة المزوّد + مرجع |
| `catalog` | `creators`, `creator_pages`, `categories`, `tags`, `follows`, `creator_team_members` | handle فريد، صفحة SFW منفصلة |
| `content` | `posts`, `post_media`, `post_audiences`, `scheduled_posts`, `drafts`, `albums` | `audience` = public/tier/ppv/segment |
| `media` | `assets`, `upload_sessions`, `renditions`, `playback_tokens`, `watermark_sessions` | حالة الأصل: uploaded→scanned→transcoded→ready→quarantined |
| `subs` | `plans`, `tiers`, `subscriptions`, `promos`, `trials`, `renewal_attempts` | فترة سماح + إعادة محاولة (dunning) |
| `billing` | `orders`, `order_items`, `payments`, `refunds`, `chargebacks`, `invoices`, `tax_records`, `psp_events` | `psp_events` جدول idempotency لمزوّد الدفع |
| `ledger` | `accounts`, `journals`, `entries`, `balances_view`, `reconciliations`, `payout_holds` | قيود مزدوجة؛ مجموع entries = 0 لكل journal |
| `payouts` | `payout_methods`, `payout_requests`, `payout_transfers`, `payout_approvals`, `statements` | أربعة أعين: منشئ ≠ معتمد |
| `msg` | `threads`, `messages`, `message_media`, `message_unlocks`, `mass_message_jobs` | فتح مدفوع = order + entitlement |
| `safety` | `reports`, `moderation_queue`, `decisions`, `appeals`, `sanctions`, `hash_matches`, `audit_log` | hash chain + الاحتفاظ القانوني |
| `notify` | `notification_prefs`, `push_tokens`, `email_log`, `outbox` | إلغاء اشتراك إشعارات إلزامي |
| `ops` | `feature_flags`, `config`, `job_runs`, `slo_events`, `incidents` | تغييرات عبر PR فقط |

**قواعد البيانات:** PostgreSQL 18+ (partitioning على `posts`, `messages`, `entries`,
`audit_log` بالشهر)، نسخة قراءة للتحليلات الثقيلة، PITR + WAL أرشفة. ClickHouse للتحليلات لا
للحقيقة. OpenSearch للبحث فقط (قابل لإعادة البناء).

### 2.4 عقود API

- REST/JSON، إصدار في المسار: `/v1/...`، وتغييرات كاسرة = `/v2`.
- مصادقة: OAuth2 (Authorization Code + PKCE) للأجهزة، JWT قصير (10 دقائق) + refresh دوّار
  مع كشف إعادة الاستخدام = إبطال الجلسة.
- كل POST مالي يقبل `Idempotency-Key` ويُخزَّن 24 ساعة على الأقل.
- Pagination بالمؤشر (cursor)، لا offset؛ حدود معدل لكل مسار ولكل مستخدم.
- أخطاء موحدة (RFC 9457 problem+json) برمز داخلي + trace id.
- OpenAPI 3.1 مُولَّد من الكود، يُنشر كـ artifact في CI، ويُختبر باختبارات تعاقد.
- نقاط حرجة: `/v1/auth/*`, `/v1/creators/{handle}`, `/v1/posts`, `/v1/media/uploads`,
  `/v1/entitlements/check`, `/v1/subscriptions`, `/v1/orders`, `/v1/messages`,
  `/v1/payouts`, `/v1/admin/*`, `/webhooks/psp/{provider}`, `/webhooks/kyc/{provider}`.

### 2.5 نظام الوسائط

1. **رفع**: جلسة resumable (S3 multipart) + رابط موقّع 15 دقيقة، حجم أقصى لكل نوع.
2. **فحص**: مطابقة بصمات CSAM (Thorn Safer / PhotoDNA) + تصنيف عري/صريح + كشف علامات مائية
   مسروقة — قبل الترميز. أي مطابقة = حجر فوري + تصعيد.
3. **ترميز**: HLS بسلّم 240/360/480/720/1080، fMP4 + AES-128 أو CENC إن لزم، صور WebP/AVIF.
4. **تسليم**: CDN مع توقيع (token + referer + geo + جلسة)، مدة الرمز 60–300 ثانية، تجزئة
   (segments) تُطلب بشكل متسلسل مع حد تزامن.
5. **علامة مائية**: نص شبه شفاف يحمل معرّف جلسة/مستخدم (forensic) + علامة مرئية اختيارية.
6. **حماية إضافية**: `FLAG_SECURE` على Android، منع التنزيل، اكتشاف تزامن جلسات غير طبيعي.

### 2.6 المال: التصميم

- **طبقة محوّلات PSP**: واجهة واحدة `PaymentProvider` (authorize, capture, refund, void,
  subscribe, cancel, webhook). التطبيق لا يعرف أي مزوّد.
- **التدفق**: order → payment attempt → webhook موقّع → `psp_events` (idempotent) →
  journal في الدفتر → entitlement → إشعار.
- **التجديد**: جدولة عبر Temporal/عامل دائم؛ المحاولات: 0، +1، +3، +7 أيام؛ ثم إلغاء مع
  إشعار. في أسواق الكروت الضعيفة: خصم من المحفظة المُسبقة الدفع.
- **العمولة**: محرك قواعد (tier بالحجم، نسبة لكل نوع معاملة، عروض خاصة) — كل تغيير له إصدار
  ومُدقَّق، ويُطبَّق على المعاملات الجديدة فقط.
- **السحب**: طلب → فحص KYC/AML → حجز في الدفتر (hold) → موافقة ثانية → تحويل عبر مزوّد →
  تسوية → كشف. فشل التحويل = إرجاع الحجز.
- **الاسترداد/الاعتراض**: سياسة مكتوبة + حدود آلية + سجل. نسبة الاعتراض > 1% تُوقف الحملات
  وتُطلق مراجعة.

### 2.7 الحماية والصلاحيات

- **Entitlement service**: قرار واحد `can(user, asset) → allow/deny + reason`، يُسجّل كل
  قرار، ويُستخدم من API/CDN token service. لا استعلام مباشر من العميل.
- **الأمان**: Argon2id لكلمات المرور، تشفير الحقول الحساسة (KMS/envelope)، TLS 1.3 فقط،
  HSTS، CSP صارم، منع SSRF، توقيع الويبهوكس + إعادة تشغيل محمية، rate-limit على المسارات
  الحساسة، حماية من التعداد (enumeration) في التسجيل/الاستعادة.
- **الخصوصية**: تقليل جمع البيانات، الاحتفاظ محدد لكل نوع (مثال: سجلات الوصول 90 يومًا،
  سجلات مالية 7 سنوات بحسب الاختصاص)، تصدير/حذف بيانات المستخدم (GDPR/CCPA)، DPIA موثّقة.
- **الأجهزة**: ربط الجهاز + حد أجهزة متزامنة، كشف مشاركة الحساب (IP/جهاز/سلوك)، تحدي تحقق
  عند الشك، وإشعار المستخدم.
- **الإدارة**: SSO (WebAuthn) + مفتاح مادي، لا كلمات مرور للإدارة، allow-list، أربعة أعين.

## 3. المخاطر المعمارية التي تحسمها الآن

| القرار | لماذا الآن | البديل إذا تأخر |
|---|---|---|
| Monolith معياري بدل microservices | فريق صغير + تكلفة تشغيل؛ حدود الوحدات تسمح بالفصل لاحقًا | إعادة كتابة مبكرة |
| PostgreSQL كمصدر حقيقة (لا NoSQL) | المال والعلاقات يحتاجان معاملات ACID | فساد أرصدة |
| محوّل دفع مجرّد | مزوّدو المحتوى الراشد يُغلقون الحسابات | إعادة كتابة الدفع بالكامل |
| محفظة مُسبقة الدفع | تجديد تلقائي في أسواق بلا كروت | فقدان أسواق كاملة |
| تطبيق أصلي + PWA (لا Play Store) | سياسة المتجر قاطعة | مشروع يتوقف عند التسليم |
| KYC/عمر عبر مزوّد متخصص | المسؤولية القانونية + متطلبات 2257/VIRP | رفض PSP |

## 4. معايير "لا تقل عن OnlyFans"

تُقاس في مرحلة القبول النهائية، لا بالرأي:

- كل وظيفة في الجدول 1.1 منفّذة ومختبرة (لا واجهات شكلية، لا بيانات تجريبية).
- مسارات المال: 100% من المعاملات تُسوّى آليًا مع تقرير فرق = 0.
- لا يمكن الوصول لأي وسيط مدفوع دون entitlement + تحقق عمر، مُثبت باختبار اختراق آلي.
- التطبيق: p95 فتح الفيديو < 1.5 ثانية، crash-free ≥ 99.5%، بدء بارد < 2 ثانية.
- الإشراف: قرار < 4 ساعات (p50)، كل قرار له أثر تدقيق.
- الفشل الجزئي: تعطّل PSP أو CDN لا يوقف المنصة (اختبار فشل مُنفَّذ).
